# JVA Volleyball Official Electronic Score Sheet

バレーボールの試合記録をブラウザー内で行う静的Webアプリです。試合・大会データは利用中のブラウザー内に保存されます。

## 主な機能

- アイコンを使わないサイドナビ付き複数画面（ホーム、取扱いマニュアル、試合設定、メンバー・ローテーション・審判登録、開始確認、試合、イベント、結果、履歴、出力）
- 試合情報（会場住所を含む）と両チームの選手・キャプテン登録
- 最大5セットの得点記録、セット・試合終了判定、直前イベントの取り消し
- タイムアウト、選手交代、警告・ペナルティ・退場・失格のイベント記録
- IndexedDBを使った試合・大会データの自動保存、最大1,000試合の履歴、JSON形式の書き出し・読み込み
- ブラウザー印刷と「PDFに保存」
- ダーク／ライトテーマ、レスポンシブ表示、Service Workerによるオフライン利用
- 詳細な大会・セット条件、8役職の審判登録（氏名・都道府県/国名）、セット別ローテーション/サーブ順
- 小学生6人制（ローテーションなし）の競技形式と、セット終了後にコートチェンジするセットの選択
- 競技形式・試合方式に応じたセット目標点の自動設定。9人制のサーブ失敗は1回目を再試行とし、2回目の失敗で相手に得点
- ソフトバレーの15点目標、2点差または17点到達によるセット終了判定
- 得点ごとのプレー種別・選手・相手選手・備考、コートチェンジのしきい値表示と記録
- 試合画面内で、コート内選手だけを選んでラリーの動作・結果をボタン記録する時系列
- 通常の選手交代とリベロ交代をイベントに残し、試合画面のコート表示とプレー選択へ反映
- タイムアウト30秒、セット終了後3分のカウントダウン
- セット終了時と最終セットの所定得点での自動コートチェンジ記録、小学生のSTO記録
- 1セットあたりチームごとに2回までの失敗チャレンジ管理（成功は回数を消費しない）
- 選択した実サーバーと登録サーブ順の照合、違反可能性のイベント記録
- 通常交代のセットごとの上限・残数表示と、リベロ交代回数・現在の出場状態・直近記録の追跡
- 大会ごとのTTO発生点2箇所の設定、自動記録と手動TTO記録
- 試合全体と各セットの経過時間表示・帳票記載
- チャレンジ判定・記録訂正・その他の得点訂正を理由付きでイベント履歴に保存
- サイドアウト率、ブレイク率、サーブ効果率、アタック決定率、レセプション成功率の試合中更新
- サーブ得点率・サーブミス率・被サービスエース率、個人のアタック決定率・被ブロック率・サーブ効果率・レセプション成功率・ブロックポイントを含む試合中の分析
- ローテーション/サーブ順別の得失点と、現在の連続得点・サーバーの表示
- セット終了時に得点、アタック得点、ブロックポイント、サービスエース、サーブ/アタックミスを集計したレポートを自動生成
- 得点推移チャート、セット/試合の最大連続得点、チーム指標による勝因比較、記録した個人成績に基づく加重MVP候補
- 試合中の簡易勝率予測（セット差と現在セットの得点差から算出。公式統計モデルによる予測ではありません）
- 試合終了時の自動総評、失点要因内訳、セット別比較、選手出場時間、異常イベント・訂正件数、得点タイムラインとイベント単位の試合リプレイ
- 試合結果画面にデータ品質スコアと減点要因（得点訂正、ローテーション整合性、サーブ順警告、記録状態チェック）を表示
- ラリー記録時のアタックゾーン、サーブの狙い先、レシーブの受球位置の指定とコース別集計。見ていない試合などコースが不明な場合は、記録しない選択が可能。サーブ/レシーブのコースは、中央に縦ネットを置いた横長コート図上に、各半面を縦3段・横2列で配置したゾーンボタンから選択
- 交代・タイムアウト後の次の3得点、コート上の得失点差、リベロのレセプション成功率・交代記録の分析
- 試合中のラインアップ重複・コート人数・交代/タイムアウト上限・リベロ交代間隔・ローテーション不整合の警告と試合終了チェック
- チーム・ベンチ・スタッフへの制裁と遅延行為の記録、セット・選手・部位・対応を残すメディカル記録
- 試合結果、メンバー表、セット結果、個人成績を選択して印刷/PDF保存
- チームコード付きのチーム履歴、コード＋背番号による選手シーズン成績の照合
- 大会モードで予選・リーグの対戦カードとトーナメント初回枠の対戦相手を手入力。トーナメントは勝者が次ラウンドへ自動進出し、アプリ外試合はセット別スコアを手入力、アプリ内試合は結果を自動反映。リーグ順位と大会試合一覧の印刷/PDFにも対応
- 大会登録した完了試合からチーム勝率（勝数÷試合数）・得セット率（取得セット÷失セット）・得失点率（得点÷失点）と、アタック得点/ブロックポイントの個人ランキングを集計。率は百分率表示で、分母が0の場合は「—」
- 大会に登録した試合の会場・コート・試合番号別進行状況と、担当試合数・担当試合中の得点訂正/チャレンジ件数を審判別に表示
- 大会ごとのマルチコート管理画面で、登録済み試合を会場・コートごとに一括表示
- 高校男子/女子、中学男子/女子、ビーチ、標準の試合テンプレート。試合開始前に競技条件へまとめて適用
- 許可された競技条件のみを含むローカルルールJSONの登録・適用・削除。任意コードやスクリプトは読み込まず、設定内容を検証して保存
- 得点・試合イベントの追加、得点訂正、取り消し、選手登録の追加/削除、試合作成/削除/JSON読み込みを、通常の試合イベントとは独立した端末内監査ログに追記。ログ全件をJSONで書き出し可能
- 大会報告書を印刷 / PDF 保存。参加チーム、順位、全試合結果、個人成績、個人成績の評価順によるMVP・ベスト6、審判成績を収録
- 保存済み試合のタイムアウト前後の記録順を使った審判トレーニング問題。答えは実データの順序であり、競技規則の正誤判定ではありません
- 審判成績に得点訂正、サーブ順違反の可能性、チャレンジ、チャレンジ判定由来の訂正件数を表示。入力者IDは未記録のため、試合担当審判全員に試合内の件数を表示
- 選手シーズン成績にチームカルテを追加。完了試合の得意・改善候補指標、ローテーション別失点、終盤失点を表示
- 選手シーズン成績に年度別勝率と直近2年度の差分を表示。チームカルテでは得点源の割合によるチームDNAと過去の起用順を基にしたスタメン/ローテーション案を表示
- 大会モードに全登録試合の得点源ヒートマップを表示（アプリ内の得点源記録が対象。外部試合の手入力スコアは除外）
- 試合イベントにメディカル記録（セット、選手、部位、対応、任意メモ）を追加。記録は端末内に保存し、個人情報・症状詳細の入力は必要最小限とする
- 試合分析にサーブミス割合、ローテーション別失点、タイムアウト後の得点を用いたルールベースの改善提案を表示。外部AIへのデータ送信は行わない
- 試合設定で動画ファイル名を登録し、動画同期画面でイベントと動画の同期ポイントを複数登録。動画本体は保存せず、イベント履歴・選手・プレー種別・ミス種別・ローテーションでクリップを抽出してシーク/連続再生
- 試合設定で、チームごとの過去完了試合に基づくサーブ・レセプション・ブロック・アタックのマッチアップ比較を表示
- 大会参加チームの保存済み完了試合を対象に最近10試合の相手チーム分析、過去対戦履歴を表示
- 保存済み試合をチーム名・期間で絞り、背番号・氏名が一致する選手の出場セット数、アタック・サーブ・レセプション・ブロック成績を累積表示
- 画面上の端末プリセット（スマートフォン/タブレット/パソコン）
- 画面イメージと手順を組み合わせた詳細な取扱いマニュアル。操作前の準備から帳票PDF・試合バックアップまで掲載
- 添付の6人制3/5セット・9人制3セット票の記載項目を参照した印刷用スコアシート
- 試合開始前のローテーション/サーブ順設定と、ネットを中央にした両チームの配置表示
- 9人制・小学生カテゴリはコートローテーションの代わりにサーブ順を表示
- チーム・選手構成とサーブ順を最大100件、履歴保存して再利用
- 試合設定・メンバー登録で設定した各チームのユニフォーム色を画面と記録票に反映
- ビーチバレーはコート内2名、9人制は9名、それ以外は6名を開始確認とサーブ順に使用
- 試合記録票はA4横向き、取扱いマニュアルはA4縦向きで印刷/PDF保存
- 得点プレーと個別プレー状態（アタック、バックアタック、ブロック、サーブ、サーブレシーブ）の記録、チーム/選手別集計表
- アタック/バックアタック決定率、セット平均、サーブ効果率、サーブレシーブ成功率を指定された計算式で自動算出

## システム設計

### アーキテクチャ

```text
ブラウザー（単一端末）
  ├─ index.html             画面、入力制約、meta CSP
  ├─ app.js                 画面遷移、入力、イベント記録、印刷票描画
  ├─ components.js          選手一覧などのDOM生成
  ├─ score.js               得点、サーブ権、ローテーション、勝敗の導出
  ├─ storage.js             データ移行・検証、IndexedDBの読み書き
  ├─ style.css              レスポンシブ画面、テーマ、印刷/PDFレイアウト
  └─ service-worker.js      同一オリジンの静的ファイルをキャッシュ
```

試合・大会データは静的ファイルとブラウザー内のIndexedDBだけで保存します。端末間の共有・同期機能はありません。PWAのService Workerはアプリファイルをキャッシュして再訪時のオフライン利用を支援します。

### データ構造

試合はIDごとに分けてIndexedDBへ保存し、大会一覧やチームプロフィールなどの共通情報と分離します。履歴を更新するときは変更された試合だけを書き込み、保存容量と更新時の負荷を抑えます。保存上限は最大1,000試合です。選手シーズン成績や大会ランキングは試合記録から表示時に集計します。JSONバックアップは現在の試合単位です。アタックゾーンはラリーイベントの任意項目として記録します。

| データ | 主な項目 |
| --- | --- |
| `matchInfo` | 大会名、日付、会場・住所、コート、試合番号、ラウンド、時刻、審判・記録員 |
| `rules` | 6/小学生6/9人制等の競技形式、カテゴリー、種別、セット数、各セット目標点、点差、タイムアウト/交代上限、コートチェンジ対象セット、ローテーション等 |
| `teams[]` | チームID・チーム名、選手、キャプテン、セット開始時のローテーション |
| `sets[]` | セット番号、最初のサーブチーム、セット開始時ラインアップ、時刻順のイベント |
| `tournaments[]` | 大会ID・名称・方式、参加チーム、対戦表、登録した保存済み試合ID |
| `events[]` | 得点、訂正、コートチェンジ、9人制サーブ失敗、タイムアウト、STO、チャレンジ、選手交代、制裁の種類・対象・時刻 |
| `rally-play`イベント | チーム/選手、プレー種別、プレー状態、備考。得点イベントと同じ時系列に保存 |
| `challenge`イベント | チーム、対象プレー、成功/失敗、時刻。失敗数はセット・チームごとに管理 |
| `technical-timeout`イベント | TTOの自動発生点または手動記録、チーム、時刻 |
| 得点訂正イベント | 訂正元の得点ID、訂正理由、チャレンジ/記録訂正などの区分を保存 |
| `service-order-violation`イベント | 利用者が選んだ実サーバーと登録順の選手、対象得点を保存。実際のサーバーを照合した時のみ判定 |
| `video` | バージョン1、動画ファイル名、イベントIDと動画秒数の同期ポイント。動画本体やBlobは保存しない |

スコア、サーブ権、ローテーション回数、セット/試合の勝敗はイベント列から導出し、表示用の重複状態は保存しません。入力時だけでなくIndexedDBへの書き込み時とJSON読み込み時にも、データ型、上限、参照ID、試合形式を検証します。古いスキーマのデータには初期値を補完してから検証します。既存のLocalStorage保存データは初回起動時に検証後IndexedDBへ移行し、移行成功後に旧保存領域を削除します。

動画は試合設定で選択している間だけFile APIと一時Object URLで再生し、ブラウザー保存領域やJSONバックアップには動画本体を含めません。再読み込みやバックアップの読み込み後はファイルを再選択してください。イベントへのシークには最も近いイベント時刻の同期ポイントを使います。異なる動画に差し替える場合は既存同期ポイントを削除して登録し直します。再生可否はブラウザーが対応する動画形式・コーデックに依存します。

### 画面・端末対応

画面遷移は左側の折りたたみナビゲーションで行い、URLハッシュにも現在画面を反映します。入力欄は画面内に並べ、横スライドを前提にしない構成です。レイアウト選択は自動/スマートフォン/タブレット/パソコンから変更できます。これは表示幅のプリセットであり、端末の物理サイズや入力装置を検出・変更する機能ではありません。

## 画面遷移

折りたたみ式の左ナビゲーションから画面を切り替えられます。大会・試合設定 → メンバー登録 → ローテーション/サーブ順設定 → 審判登録 → 開始確認 → 「試合を開始する」の順に進めます。未開始状態で試合画面を選んだ場合も開始確認へ誘導されます。6人制の位置表示はコートをネットで左右に分け、横2人・縦3人で表します。チームAは左下の位置1から反時計回り、チームBは右上の位置1から反時計回りです。チームAを青、チームBをオレンジで表示します。9人制または小学生カテゴリでは、コートローテーションの代わりにサーブ順と現在のサーバーを表示します。チーム履歴はチーム名、選手、キャプテン、サーブ順を同じ端末に保存し、トーナメントでの再対戦時に呼び出せます。試合開始後は試合条件やチーム履歴を変更できません。画面の選択はURLのハッシュにも反映され、再読み込み後も同じ画面へ戻ります。端末プリセットは表示幅を切り替えるためのUI設定であり、接続端末の検出や実機の物理寸法変更ではありません。

## プレーデータと記録票

- 得点時には「+1」から、サービスエース、アタック、バックアタック、ブロック等の得点プレーを選びます。選手が登録されている場合はプレー選手を選択してください。この得点プレーはプレー記録にも集計されるので、同じ得点をイベント管理から重複して登録しないでください。
- 得点以外の個々の状態は「イベント管理 → プレー状態を記録」から、チーム、選手、プレー、結果を選んで記録します。アタック/バックアタック/ブロック/サーブの失点・継続状態、サーブの効果あり、レシーブの成功（優/良）等を入力できます。
- 記録票はチーム別・選手別にアタック、バックアタック、ブロック、サーブ、サーブレシーブの件数をまとめます。チーム合計と選手ごとの内訳を表示し、チームAは青、チームBはオレンジで区別します。
- アタック/バックアタック決定率は得点数 ÷ 打数 × 100、アタックおよびブロックのセット平均は得点数 ÷ 出場セット数です。
- サーブ効果率は（サービスエース × 100 ＋ 効果 × 25 − サーブ失点 × 25）÷ サーブ打数、サーブレシーブ成功率は（優 × 100 ＋ 良 × 50）÷ 受数で計算します。サービスエースは得点記録から効果数にも自動計上し、サーブ打数は1本として数えます。
- サーブの「効果」はノータッチエースを含み、レシーブを大きく崩してセッター以外の選手が2本目を処理した場合に記録します。「優」は狙い通りのコンビネーションが使える返球、「良」はセッターが動いても攻撃につながる返球です。
- 率は小数第1位、セット平均は小数第2位まで表示します。分母が0の場合は「—」を表示します。出場セット数は先発ラインアップまたは交代出場の記録から数えます。
- ラリー中の個別プレーはイベント管理画面から、チーム・選手・動作・結果を選択して記録します。得点イベントと同じ時系列で保存され、「ラリー・イベント記録」を選ぶとプレーの流れを印刷できます。
- チャレンジはチーム、対象プレー、判定結果をセットごとに記録します。失敗が2回に達したチームは、それ以上失敗として登録できません。成功は失敗数に加算しません。
- 通常タイムアウトを記録すると30秒、セット終了時は3分のカウントダウンを表示します。小学生の3セットマッチ第3セットは、いずれかのチームが11点に到達した際にSTOを自動記録します。STOは通常タイムアウト回数に含めず、イベント履歴には残します。
- 第1〜第2セット（3セットマッチ）または第1〜第4セット（5セットマッチ）の終了時にコートチェンジを記録します。最終セットは目標25点なら13点、21点なら8点、小学生3セットマッチの第3セットなら8点で自動記録します。
- 「データ出力」から出力する記録票を選択します。試合記録、得点・コートチェンジ記録、ラリー・イベント記録、取扱いマニュアルを個別にプレビューし、ブラウザーの印刷画面からPDF保存できます。

## ローカルでの確認

`index.html`を直接開くのではなく、VS CodeのLive Serverなど静的ファイルを配信する方法で開いてください。ES ModulesとService Workerは`file://`では正しく動作せず、Service WorkerはHTTPSまたはlocalhostが必要です。公開時にはGitHub PagesのURLを使えます。

## GitHub Pagesで公開

1. GitHubで空のリポジトリを作成します。
2. このフォルダー内のファイルをリポジトリのルートへ追加し、GitHubへpushします。
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment** の Sourceで **Deploy from a branch** を選択します。
5. 公開するブランチ（通常は`main`）とフォルダー（通常は`/(root)`）を選択し、保存します。
6. 表示されたGitHub Pages URLでアプリを開き、オフライン再起動、印刷、バックアップ読み込みを確認します。インストール可能なPWA表示はブラウザーによって異なります（アイコンは含めていません）。

ビルド工程・有料サービス・独自ドメインは不要です。リポジトリがprivateの場合のPages利用条件はGitHubのプラン設定に従います。

## 保存とバックアップ

- 試合・大会データは現在の端末・ブラウザーのIndexedDBに保存されます。他の端末への自動同期はありません。端末やブラウザーの利用可能容量に依存し、保存上限は最大1,000試合です。
- 既存データは初回起動時にLocalStorageからIndexedDBへ自動移行します。移行に失敗した場合、旧データは削除せず、復旧が必要な状態として表示します。
- IndexedDBのデータもブラウザーのデータ削除や端末故障などで失われる場合があります。重要な試合では「データ書き出し」でJSONファイルを別の安全な場所へ保存してください。
- 「データ読み込み」はこのアプリが書き出した形式のJSONのみを受け付け、読み込み前に構造・型・件数を検証します。
- 自動保存失敗時は画面上部にエラーを表示します。保存済みと表示されていても、試合後にJSONバックアップを取得してください。

### ローカルルール設定

試合設定の「ローカルルールJSONを登録」から、`id`・`name`・`settings`を持つJSONを登録できます。`settings`で指定できるのは競技形式、カテゴリー、種別、セット数、目標点、点差、タイムアウト/交代上限、登録人数、ローテーション、ウォームアップ、コートチェンジ間隔、テクニカルタイムアウト発生点です。未知のキーや範囲外の値は拒否し、JSON内のコード・スクリプトは実行しません。ローカル設定は端末内に保存され、JSONとして書き出して別端末へ移せます。

## ルール・公式利用に関する注意

標準目標点は競技形式・試合方式の選択に応じて自動設定します。6人制は通常25点・最終15点、小学生6人制/9人制/ビーチバレーは通常21点・最終15点、ソフトバレーは全セット15点です。ソフトバレーは2点差がつくか、いずれかのチームが17点に達するとセット終了です。目標点やタイムアウト上限は試合開始前に確認してください。最初のイベント記録後はルール変更をロックし、途中変更による判定の変化を防ぎます。

これは記録支援の実装であり、JVA公式システムとして認定されたものではありません。印刷票は添付資料に含まれる項目を試合進行に合わせて反映するHTML票で、公式用紙の原本と同一レイアウト・同一様式を保証するものではありません。実大会で利用する前に、対象カテゴリの最新競技規則、大会要項、交代・タイムアウト等の運用、公式記録票の必要項目と照合し、複数端末・実試合で十分に受入試験してください。リベロ交代・通常交代は記録と回数表示を行いますが、規則適合を完全に判定するものではありません。サーブ順の警告は利用者が実際のサーバーを選択した場合に登録順と照合するもので、選手の動作を自動認識する機能ではありません。各分析、コース割合、交代・タイムアウト後の得失点、リプレイは入力記録から作成する参考情報で、因果関係を示すものではありません。レシーブ位置の成功率は「優・良」の比率です。コース分析は位置を入力したプレーだけが対象です。試合データは利用中のブラウザー内に保存され、別端末との共有・同期は行いません。動画連携では動画本体を保存せず、再読み込み後は対象ファイルを再選択する必要があります。

## セキュリティと運用上の制約

- DOM要素を生成し、入力値の画面表示には`textContent`を使います。`innerHTML`、`eval`、`Function`コンストラクターは使用しません。
- 入力項目には文字数上限を設定し、保存・読み込み時にはスキーマ、値の型、範囲を再検証します。
- HTMLのmeta CSPで同一オリジンのリソースに制限しています。GitHub PagesではHTTPレスポンスヘッダーを自由に設定できず、meta CSPでは適用できない指令もあるため、サーバー設定と同等の保護を保証するものではありません。
- Service Workerは初回訪問時にアプリファイルをキャッシュします。初回読み込みと更新の取得にはネットワークが必要です。コード更新後に反映されない場合はページを再読み込みしてください。
- アプリファイルを更新して公開するときは、`service-worker.js`の`CACHE_NAME`末尾のバージョンも上げてください（現在は`v61`）。新しいキャッシュへの切替時に古いバージョンは削除されます。
- 監査ログは端末内ブラウザーのIndexedDBに追記し、アプリ画面からの編集・削除機能はありませんが、暗号学的な改ざん検知やユーザー認証はありません。端末や開発者ツールからの変更を防ぐものではないため、公式大会での単独の正本として使う場合は、端末管理、バックアップ、訂正手順を含む運用設計が別途必要です。
