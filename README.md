# JVA Volleyball Official Electronic Score Sheet

バレーボールの試合記録をブラウザー内で行う静的Webアプリです。HTML、CSS、Vanilla JavaScriptだけで動作し、サーバー、データベース、ログイン、外部APIは使用しません。

## 主な機能

- アイコンを使わないサイドナビ付き複数画面（ホーム、取扱いマニュアル、試合設定、メンバー・ローテーション・審判登録、開始確認、試合、イベント、結果、履歴、出力）
- 試合情報と両チームの選手・キャプテン登録
- 最大5セットの得点記録、セット・試合終了判定、直前イベントの取り消し
- タイムアウト、選手交代、警告・ペナルティ・退場・失格のイベント記録
- LocalStorage自動保存、試合履歴、JSON形式の書き出し・読み込み
- ブラウザー印刷と「PDFに保存」
- ダーク／ライトテーマ、レスポンシブ表示、Service Workerによるオフライン利用
- 詳細な大会・セット条件、8役職の審判登録（氏名・都道府県/国名）、セット別ローテーション/サーブ順
- 得点ごとのプレー種別・選手・相手選手・備考、コートチェンジのしきい値表示と記録
- 試合画面内で、コート内選手だけを選んでラリーの動作・結果をボタン記録する時系列
- 通常の選手交代とリベロ交代をイベントに残し、試合画面のコート表示とプレー選択へ反映
- タイムアウト30秒、セット終了後3分のカウントダウン
- セット終了時と最終セットの所定得点での自動コートチェンジ記録、小学生のSTO記録
- 1セットあたりチームごとに2回までの失敗チャレンジ管理（成功は回数を消費しない）
- 画面上の端末プリセット（スマートフォン/タブレット/パソコン）
- 画面イメージと手順を組み合わせた詳細な取扱いマニュアル。操作前の準備から帳票PDF・JSONバックアップまで掲載
- 添付の6人制3/5セット・9人制3セット票の記載項目を参照した印刷用スコアシート
- 試合開始前のローテーション/サーブ順設定と、ネットを中央にした両チームの配置表示
- 9人制・小学生カテゴリはコートローテーションの代わりにサーブ順を表示
- チーム・選手構成とサーブ順を最大100件、LocalStorageに履歴保存して再利用
- 試合設定・メンバー登録で設定した各チームのユニフォーム色を画面と記録票に反映
- ビーチバレーはコート内2名、9人制は9名、それ以外は6名を開始確認とサーブ順に使用
- 試合記録票はA4横向き、取扱いマニュアルはA4縦向きで印刷/PDF保存
- 得点プレーと個別プレー状態（アタック、バックアタック、ブロック、サーブ、サーブレシーブ）の記録、チーム/選手別集計表
- アタック/バックアタック決定率、セット平均、サーブ効果率、サーブレシーブ成功率を指定された計算式で自動算出

## システム設計

### アーキテクチャ

```text
ブラウザー（単一端末）
  ├─ index.html             画面、入力制約、meta CSP
  ├─ app.js                 画面遷移、入力、イベント記録、印刷票描画
  ├─ components.js          選手一覧などのDOM生成
  ├─ score.js               得点、サーブ権、ローテーション、勝敗の導出
  ├─ storage.js             データ移行、検証、LocalStorageの読み書き
  ├─ style.css              レスポンシブ画面、テーマ、印刷/PDFレイアウト
  └─ service-worker.js      同一オリジンの静的ファイルをキャッシュ
```

静的ファイルだけで動作するクライアントサイド構成です。試合情報を送信するサーバーや外部APIはありません。PWAのService Workerはアプリファイルをキャッシュして再訪時のオフライン利用を支援します。初回訪問時とアプリ更新の取得にはネットワークが必要です。

| 審判登録 | 8役職の氏名、都道府県または国名 |
| 開始確認 | 試合条件、登録状況、ネットを中央にした配置と最初のサーバーの確認 |

### データ構造

保存単位は1試合です。複数試合はLocalStorage内の履歴として保持します。

| データ | 主な項目 |
| --- | --- |
| `matchInfo` | 大会名、日付、会場、コート、試合番号、ラウンド、時刻、審判・記録員 |
| `rules` | 6/9人制、カテゴリー、種別、セット数、各セット目標点、点差、タイムアウト/交代上限、ローテーション等 |
| `teams[]` | チームID・チーム名、選手、キャプテン、セット開始時のローテーション |
| `sets[]` | セット番号、最初のサーブチーム、セット開始時ラインアップ、時刻順のイベント |
| `events[]` | 得点、訂正、コートチェンジ、タイムアウト、STO、チャレンジ、選手交代、制裁の種類・対象・時刻 |
| `rally-play`イベント | チーム/選手、プレー種別、プレー状態、備考。得点イベントと同じ時系列に保存 |
| `challenge`イベント | チーム、対象プレー、成功/失敗、時刻。失敗数はセット・チームごとに管理 |

スコア、サーブ権、ローテーション回数、セット/試合の勝敗はイベント列から導出し、表示用の重複状態は保存しません。入力時だけでなくLocalStorageへの書き込み時とJSON読み込み時にも、データ型、上限、参照ID、試合形式を検証します。古いスキーマのデータには初期値を補完してから検証します。

### 画面・端末対応

画面遷移は左側の折りたたみナビゲーションで行い、URLハッシュにも現在画面を反映します。入力欄は画面内に並べ、横スライドを前提にしない構成です。レイアウト選択は自動/スマートフォン/タブレット/パソコンから変更できます。これは表示幅のプリセットであり、端末の物理サイズや入力装置を検出・変更する機能ではありません。

## 画面遷移

折りたたみ式の左ナビゲーションから画面を切り替えられます。大会・試合設定 → メンバー登録 → ローテーション/サーブ順設定 → 審判登録 → 開始確認 → 「試合を開始する」の順に進めます。未開始状態で試合画面を選んだ場合も開始確認へ誘導されます。6人制の位置表示はコートをネットで左右に分け、横2人・縦3人で表します。チームAは左下の位置1から反時計回り、チームBは右上の位置1から反時計回りです。チームAを青、チームBをオレンジで表示します。9人制または小学生カテゴリでは、コートローテーションの代わりにサーブ順と現在のサーバーを表示します。チーム履歴はチーム名、選手、キャプテン、サーブ順を同じ端末に保存し、トーナメントでの再対戦時に呼び出せます。試合開始後は試合条件やチーム履歴を変更できません。画面の選択はURLのハッシュにも反映され、再読み込み後も同じ画面へ戻ります。端末プリセットは表示幅を切り替えるためのUI設定であり、接続端末の検出や実機の物理寸法変更ではありません。

## プレーデータと記録票

- 得点時には「+1」から、サービスエース、アタック、バックアタック、ブロック等の得点プレーを選びます。選手が登録されている場合はプレー選手を選択してください。この得点プレーはプレー記録にも集計されるので、同じ得点をイベント管理から重複して登録しないでください。
- 得点以外の個々の状態は「イベント管理 → プレー状態を記録」から、チーム、選手、プレー、結果を選んで記録します。アタック/バックアタック/ブロック/サーブの失点・継続状態、サーブの効果あり、レシーブの成功（優/良）等を入力できます。
- 記録票はチーム別・選手別にアタック、バックアタック、ブロック、サーブ、サーブレシーブの件数をまとめます。チーム合計と選手ごとの内訳を表示し、チームAは青、チームBはオレンジで区別します。
- アタック/バックアタック決定率は得点数 ÷ 打数 × 100、アタックおよびブロックのセット平均は得点数 ÷ 出場セット数です。
- サーブ効果率は（サービスエース × 100 ＋ 効果 × 25 − サーブ失点 × 25）÷ サーブ打数、サーブレシーブ成功率は（優 × 100 ＋ 良 × 50）÷ 受数で計算します。サービスエースは得点記録から効果数にも自動計上し、サーブ打数は1本として数えます。
- サーブの「効果」はノータッチエースを含み、レシーブを大きく崩してセッター以外の選手が2本目を処理した場合に記録します。「優」は狙い通りのコンビネーションが使える返球、「良」はセッターが動いても攻撃につながる返球です。
- 率は小数第1位、セット平均は小数第2位まで表示します。分母が0の場合は「—」を表示します。出場セット数は先発ラインアップまたは交代出場の記録から数えます。
- ラリー中の個別プレーはイベント管理画面から、チーム・選手・動作・結果を選択して記録します。得点イベントと同じ時系列で保存され、「ラリー・イベント記録」を選ぶとプレーの流れを印刷できます。
- チャレンジはチーム、対象プレー、判定結果をセットごとに記録します。失敗が2回に達したチームは、それ以上失敗として登録できません。成功は失敗数に加算しません。
- 通常タイムアウトを記録すると30秒、セット終了時は3分のカウントダウンを表示します。小学生の3セットマッチ第3セットは、いずれかのチームが11点に到達した際にSTOを自動記録します。STOは通常タイムアウト回数に含めず、イベント履歴には残します。
- 第1〜第2セット（3セットマッチ）または第1〜第4セット（5セットマッチ）の終了時にコートチェンジを記録します。最終セットは目標25点なら13点、21点なら8点、小学生3セットマッチの第3セットなら8点で自動記録します。
- 「データ出力」から出力する記録票を選択します。試合記録、得点・コートチェンジ記録、ラリー・イベント記録、取扱いマニュアルを個別にプレビューし、ブラウザーの印刷画面からPDF保存できます。

## ローカルでの確認

`index.html`を直接開くのではなく、VS CodeのLive Serverなど静的ファイルを配信する方法で開いてください。ES ModulesとService Workerは`file://`では正しく動作せず、Service WorkerはHTTPSまたはlocalhostが必要です。公開時にはGitHub PagesのURLを使えます。

## GitHub Pagesで公開

1. GitHubで空のリポジトリを作成します。
2. このフォルダー内のファイルをリポジトリのルートへ追加し、GitHubへpushします。
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment** の Sourceで **Deploy from a branch** を選択します。
5. 公開するブランチ（通常は`main`）とフォルダー（通常は`/(root)`）を選択し、保存します。
6. 表示されたGitHub Pages URLでアプリを開き、オフライン再起動、印刷、バックアップ読み込みを確認します。インストール可能なPWA表示はブラウザーによって異なります（アイコンは含めていません）。

ビルド工程・有料サービス・独自ドメインは不要です。リポジトリがprivateの場合のPages利用条件はGitHubのプラン設定に従います。

## 保存とバックアップ

- 試合データは現在の端末・ブラウザーのLocalStorageに保存されます。他の端末への自動同期はありません。
- LocalStorageはブラウザーのデータ削除や端末故障などで失われる場合があります。重要な試合では「データ書き出し」でJSONファイルを別の安全な場所へ保存してください。
- 「データ読み込み」はこのアプリが書き出した形式のJSONのみを受け付け、読み込み前に構造・型・件数を検証します。
- 自動保存失敗時は画面上部にエラーを表示します。保存済みと表示されていても、試合後にJSONバックアップを取得してください。

## ルール・公式利用に関する注意

既定値は5セットマッチ、通常セット25点、最終セット15点、2点差、1セット2回のタイムアウトです。画面の試合形式・目標点・タイムアウト上限は試合開始前に設定できます。最初のイベント記録後はルール変更をロックし、途中変更による判定の変化を防ぎます。

これは記録支援の実装であり、JVA公式システムとして認定されたものではありません。印刷票は添付資料に含まれる項目を試合進行に合わせて反映するHTML票で、公式用紙の原本と同一レイアウト・同一様式を保証するものではありません。実大会で利用する前に、対象カテゴリの最新競技規則、大会要項、交代・タイムアウト等の運用、公式記録票の必要項目と照合し、複数端末・実試合で十分に受入試験してください。現状はリベロ交代、選手交代の規則適合判定など、公式記録に必要となるすべての情報を管理するものではありません。規則違反の自動判定や複数端末同期も行いません。

## セキュリティと運用上の制約

- DOM要素を生成し、入力値の画面表示には`textContent`を使います。`innerHTML`、`eval`、`Function`コンストラクターは使用しません。
- 入力項目には文字数上限を設定し、保存・読み込み時にはスキーマ、値の型、範囲を再検証します。
- HTMLのmeta CSPで同一オリジンのリソースに制限しています。GitHub PagesではHTTPレスポンスヘッダーを自由に設定できず、meta CSPでは適用できない指令もあるため、サーバー設定と同等の保護を保証するものではありません。
- Service Workerは初回訪問時にアプリファイルをキャッシュします。初回読み込みと更新の取得にはネットワークが必要です。コード更新後に反映されない場合はページを再読み込みしてください。
- アプリファイルを更新して公開するときは、`service-worker.js`の`CACHE_NAME`末尾のバージョンも上げてください（現在は`v16`）。新しいキャッシュへの切替時に古いバージョンは削除されます。
- このアプリは権限管理・操作監査ログ・バックエンド保護を持ちません。公式大会での単独の正本として使う場合は、端末管理、バックアップ、訂正手順を含む運用設計が別途必要です。
